# 验布机读数对齐与复验清单 v1（loom-inspect）

使用者为样布质检工段。织造结束后布卷上验布机：验布机按采集顺序输出帧，每帧给出编码器纬区间、若干经端的组织采样和该帧自带的布面缺陷检出。编码器回跳会重拍同一纬（步长 0），掉帧会跳过几纬（步长大于 1），因此验布机的读取序号不等于成布的纬序号；同一批读数有时能和成布组织对上不止一条路线。本接口把全部帧读数与既有排产计划对齐，在**所有**完整对齐路线上做保守判定，回答每块待切裁区：可以结束布面检查（`clear`）、肯定有表面缺陷（`damaged`）、还是必须复验（`recheck`）。

本接口只增加验布语义，**不改变** `loom-draft`、`loom-batch`、`loom-trace`、`loom-dispatch` 的行为。批次计划由现有 `run_plan` 规则唯一确定（价值最大、总用纱最小、身份键最小），验布证据不能使系统重选方案。这里的结论仅用于布面检查，不等于原料放行（loom-trace）或实际发货（loom-dispatch）。

## 输入

严格 JSON 对象，顶层字段恰为 `batch`、`probe_ends`、`frames`、`cuts`。所有整数拒绝布尔值；未知字段、重复键、非有限常量、越界位置均为输入错误；每行、每项都先完整验证再计算。

### batch

现有合法批次输入（校验同 `docs/contract-batch.md`），按原排产规则得到唯一计划。计划共 P 条实际纬、E = `len(common.warp) × common.repeat_x` 根实际经端，基础穿综长 M = `len(common.warp)`。所有物理坐标从 0 开始。

真实纬的组织来自计划中覆盖该纬的压缩段：按段内周期取行，段周期使用排产选定相位，接缝也是实际织出的纬。经端 x 对应该行的基础位置 `x % M`，组织值 1 表示经在纬上。本接口复用现有计划和组织编译，不另定义踏板或相位规则。

### probe_ends

1..8 个互异的实际经端索引（0 <= x < E），数组顺序决定帧中采样位的顺序。

### frames

1..120000 行，验布机按采集顺序输出，顺序不可重排。每行恰是 `[lo, hi, min_step, max_step, sample, defect]`：

* `[lo, hi]`：编码器给出的该帧可能所在纬的闭区间，`0 <= lo <= hi < P`，至多含 512 条纬。
* `min_step`、`max_step`：首帧均为 0；其余帧满足 `0 <= min_step <= max_step <= 4`，表达相对于上一帧的前进量。步长 0 是重拍，步长大于 1 是跳拍。允许扫描从卷布中段开始或提前结束。
* `sample`：与 `probe_ends` 等长的字符串，只含 `0`、`1`、`?`。在候选纬上所有非问号位必须等于计划的组织值；问号只表示此探针读不到花纹，不影响该帧自带的布面检查结果。
* `defect`：`null` 表示这帧未检出表面缺陷，否则为 `[end_start, end_stop]`，表示该帧在这段横向半开区间检测到缺陷，`0 <= end_start < end_stop <= E`。每帧拍摄整条实际纬的幅宽。同一纬有多次拍摄时，任何一帧的缺陷都算证据；重拍的干净帧不能消掉先前的缺陷。

### cuts

0..32 个对象，每个恰含 `id`、`end_start`、`end_stop`、`pick_start`、`pick_stop`：

* `id`：匹配 `[A-Za-z0-9_-]{1,40}`，数组内唯一；
* 矩形为正面积，端点是经端和纬的半开边界，须位于成布内：`0 <= end_start < end_stop <= E`，`0 <= pick_start < pick_stop <= P`。

允许查询互相重叠的候选裁区，因为还没裁切。

空生产计划（P = 0）仅允许 `probe_ends`、`frames`、`cuts` 都为空，仍给出成功空报告。

## 对齐语义

一条合法对齐是给所有帧各指定一条实际纬，且同时满足：每帧的纬落在各自窗口内、组织读数与计划一致（非问号位）、相邻帧纬差落在各自步长区间（`pick[i] - pick[i-1]` 在 `[min_step[i], max_step[i]]` 内）。

局部满足一帧条件的位置不一定能出现在任何完整对齐中，判定只依据完整对齐。非空扫描没有任何完整对齐时，说明编码器或组织数据不自洽，整体报输入错误，不发出裁区结论。

只要有对齐，就保留以下业务意义上的全部可能性：不能用先找到的一条路线判通过，也不能把分别在不同路线中拍到的纬合起来，声称有一条路线把它们全验过。

* **确定验过**：一条纬只有在**每条**完整对齐中都至少被一帧拍到才算确定验过。可以是不同对齐中的不同帧；同一纬被重拍也只记一次。不能把某帧的窗口当成覆盖范围，或只统计位置唯一的帧。
* **可能缺陷**：一块裁区可能有缺陷，当且仅当**至少一条**完整对齐中有缺陷帧落在裁区纬区间，且缺陷横向范围与裁区经端区间有正宽度交集。缺陷横向区间恰好与裁区相接不算命中。
* **确定缺陷**：若**每条**完整对齐中都至少有一个这样的缺陷帧，裁区确定有缺陷，哪怕各路线中的缺陷帧或真实纬不同。

## 裁区处置

* `damaged`：确定有缺陷的裁区。仍要报告哪些纬无法确认检查覆盖。
* `recheck`：其余裁区只要有可能缺陷或未确定验过的纬。
* `clear`：只有整块的纬都确定验过且没有可能缺陷。

补进定位证据导致某些完整路线消失后，处置结论要随之改变，即便缺陷图像和裁区都没变。

## 输出报告

`schema_version=1`，CLI 与 `loom_draft.inspection.run_inspection(data)` 返回结构一致；后者返回普通字典，非法输入抛 `ValueError`。

* `plan`、`segments`：原计划的计划身份与压缩段，结构不变。
* `cuts`：按 `id` 的 ASCII 顺序，每项含：
  * `id`、`status`（`clear` / `recheck` / `damaged`）、`certain_defect`（布尔）；
  * `possible_defect`：无可能缺陷为 `null`，否则为 `{pick_index, frame_index, end_start, end_stop}`，用真实纬序号、0 起始帧下标及该帧缺陷与裁区横向相交的范围；在全部可命中的位置中先取最小 `pick_index`，再取最小 `frame_index`；
  * `forced_observed_picks`：裁区纬区间内确定验过的纬数；
  * `first_unconfirmed_pick`：该裁区最早一条并非确定验过的实际纬，全覆盖时为 `null`。
* `summary`：至少含 `clear`、`recheck`、`damaged` 三种裁区计数及裁区总数 `cuts`。

组织扫描再模糊也不输出所有路线或逐交织点报告。

## 资源与实现约束

验布工段的离线机给此子进程 192 MiB 地址空间。实现必须在限制内完成 JSON 读取、排产、对齐、裁区决策和输出：帧数至多 120000、窗口至多 512 纬、步长至多 4、P 与 E 到既有批次上限；不展开任一整卷交织网格，不枚举所有完整路线，不擅自缩小输入窗口与合法步长上限，在上述资源范围内保持精确性。仅依赖 Python 标准库，处理本地合成输入，无需机台、网络或数据库。不设耗时门槛。

## CLI 与失败约定

`loom-inspect --source INPUT --output OUTPUT`。沿用严格载入（JSON 最多 8MB、拒绝重复键与非有限常量）、先完整验证与计算、再同目录临时文件原子硬链接新建一个 JSON 报告的约定。

* 有复验和缺陷结论的有效报告仍成功退出 0，并向标准输出打印 `summary`；
* 非法输入、无完整对齐、目标已存在及 I/O 错误退出 2；
* 不把 traceback 当作报告，不覆盖既有目标或留下部分报告。

## 大场景验收（可复现）

```sh
python3 examples/inspection_acceptance.py run/big_input.json
.venv/bin/loom-inspect --source run/big_input.json --output run/big_report.json
```

128 纬平纹周期重复 1000 次、横向重复 1000 次的有库存批次（128000 纬 × 2000 经端）；120000 帧：首帧固定纬 0，下标 i=1..119998 的窗口 [i, i+511]、步长 1..2，末帧固定纬 120510、步长 1..2，探针全问号、无缺陷。任一完整对齐首尾之间总共跳过 511 纬，每一条内部纬都能在某条完整对齐中被跳过：整卷裁区 [0,120511) 确定验过 2 纬、最早未确认纬 1，判 `recheck`；只查纬 120510 的裁区判 `clear`。预期 summary：`{"clear": 1, "cuts": 2, "damaged": 0, "recheck": 1}`。
