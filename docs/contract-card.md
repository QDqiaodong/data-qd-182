# 共用绑综的连续织造工艺卡 v1（loom-card）

使用者为织机工艺准备工段。技术员已拿到若干款样布的目标组织图；装机时只
调整一次踏板绑综，每款在开织前可另选自己的常态踩法。本接口反过来选出一
套各款共用的绑综，并把每款常态踩法与该款每个单拍故障的应急踩法一起交给
只会照卡执行的机台。

机台按固定拍速推进，不能插入空拍或跳过应织的纬；这里不选工单、不消耗
库存、不安排各款之间的接缝。每款必须独立通过；换款时停机，前款的踏板
状态不传给后款。本接口与 v1（loom-draft）共用同一份组织编译语义：同一拍
升起的综框是该拍所踩踏板所绑综框的并集，`1` 表示该经端在纬纱上方。不连
接织机、不做近似匹配。

## 输入

严格 JSON 对象，顶层字段恰为 `shafts`、`warp`、`pedals`、`max_pressed`、
`blocked_pairs`、`patterns`、`rejoin_limit`。所有声明先完整验证再计算；
未知字段、重复标识、布尔冒充整数均为输入错误。

* `shafts`：整数 1..16。
* `warp`：1..128 个经端，每端恰含 `shaft`（1..`shafts`）与 `yarn`（v1 纱线
  标签规则）。这是基础穿综；每个经端恰穿一根综框。
* `pedals`：1..8 项，每项恰含 `id`、`current`、`options`。
  * `id` 沿用旧织机踏板 ID 规则（非空、≤200 字符、区分大小写），在
    `pedals` 内唯一。
  * `options` 为 1..3 个互异的综框集合，每个以整数数组给出，元素为
    1..`shafts` 且不可重复；空集合合法。成员顺序无意义。
  * `current` 是其中一个集合，也是装机前的实物绑法。两个踏板允许绑同一组。
* `max_pressed`：整数 1..3，单拍能同时踩的踏板数上限。
* `blocked_pairs`：0..28 个二元踏板 ID 数组。两个 ID 必须存在且互异；对调
  两项视为同一对，不得重报。每拍不能同时踩中任一禁配对。
* `patterns`：1..6 项，每项恰含 `id`、`rows`、`faults`。
  * `id` 匹配 `[A-Za-z0-9_-]{1,40}`，在款集合内唯一。
  * `rows` 为 1..48 个从第 0 纬起按顺序排列的位串，每串长度为 `len(warp)`，
    只含 `0`、`1`；序列原样周期性无限循环。若同一综框的两根经端在某纬要求
    相反，这是有意义但织不出的图样，按无可用工艺卡处理。没有经端穿过的综框
    可以升降，只按实有经端判断组织是否相等。
  * `faults` 为 0..96 对 `[row, pedal_id]`。`row` 为该款 0 起的周期内纬号，
    `pedal_id` 必须已声明；同一对不可重报。每对表示必须可处置的一种单独
    故障：已按该款同一常态周期织到此前一拍，下一拍开始前机台得知此踏板只
    在这一拍不能踩。之后踏板立即可用，冷却仍按实际踩中与否计算。各场景
    互斥，不要求处理应急期间的第二次故障；即使常态本来就不踩故障踏板，
    也要交付这对的处置步骤。
* `rejoin_limit`：整数 0..3，故障拍过后允许再用多少拍应急踩法。

款号和踏板标识比较区分大小写；输入数组次序不用于选择结果（目标 `rows` 的
拍序除外）。

## 可行工艺卡

工艺卡由一套共用绑综、每款一张常态表、以及每个故障的一条应急串组成，须
同时满足：

1. **共用绑综 + 常态表。** 同一套绑综给所有款使用；每款常态表恰有
   `len(rows)` 拍，逐拍织出对应目标位串，遵守同时踩上限、禁配对，以及
   “任一踏板踩过后须空过一整拍才能再次踩”（相邻两拍踩中的踏板不能重叠，
   包括常态每轮的首尾）。常态表可按同一周期原样无限循环。同一款的不同
   故障不得预先选不同常态表。
2. **应急串。** 每个故障场景给出一串应急实际踩法，从故障拍起织连续的目标
   纬，共 k 拍，1 ≤ k ≤ 1+`rejoin_limit`；跨周期尾时目标纬继续回到第 0 纬。
   只有第 0 个应急动作受本次失灵踏板限制（不得踩故障踏板），之后的应急
   动作不受该限制。逐拍检查组织、同时踩、禁配、冷却：首拍还要与真实前一拍
   的常态踩法相容，末拍还要与其后第一拍的指定常态踩法相容。接回发生在
   应急串之后，不需要重开周期，也不能进入另一份常态周期。机台会执行返回
   的具体踩法，不能只给“可应急”的布尔结论。

一个完全由常态表与故障决定的辅助事实：即使常态本来就不踩某故障踏板，
也必须交付该对故障的应急步骤。

## 选卡与平局

在所有可用卡中依次选择：

1. 改变 `current` 绑综集合的踏板数最少；
2. 踏板按 ID 升序排列后，各踏板所绑综框的升序整数列表组成的序列字典序
   最小；
3. 仍同分时，按款号升序排列、每款从第 0 纬开始的常态踩法序列字典序最小。

一次踩法先把踏板 ID 按 ASCII 升序排列，再做列表字典序比较；全部分层列表
均使用通常逐项字典序（真前缀较小）。固定胜出的卡及常态表之后，各故障先
取最短有效应急串，再取踩法序列字典序最小的一串。应急串长度不参与绑综或
常态表的排序，不能用单款局部最优、只检查常态、或固定先选某一套绑综再判
整单失败替代全局规则。

## 输出报告

`schema_version=1`；成功 `status="ready"`：

* `changed_pedals`：柜台要改绑的踏板数（所绑综框集合与 `current` 不同的
  踏板数）。
* `tie_up`：按 `id` 排序的 `{id, shafts}` 列表，可直接作为旧接口的绑综。
* `patterns`：按款号排序，每项含：
  * `id`；
  * `picks`：按目标纬序排列的踏板 ID 列表的数组（每拍内部按 ID 升序）；
  * `fault_playbook`：按 `(row, pedal_id)` 排序，每条恰含 `row`、`pedal_id`、
    `picks`（应急串，每拍内部按 ID 升序）、`resume_row`，其中 `resume_row`
    为 `(row + len(picks))` 对纬数取模。

合法输入但不存在可用卡时 `status="infeasible"`，`changed_pedals` 为
`null`，`tie_up` 与 `patterns` 均为空数组，不返回部分可用卡。

## CLI 与失败约定

`loom-card --source INPUT --output OUTPUT`。沿用仓库严格载入（JSON 最多
8 MB、拒绝重复键与非有限常量）、先完整验证与计算、再同目录临时文件原子
硬链接新建一个 JSON 报告。`ready` 与 `infeasible` 均退出 0 并向标准输出打印
摘要；非法输入、I/O 错误或已存在的报告目标退出 2，保留原目标且不留半份
报告。Python 接口 `loom_draft.card.run_card(data)` 返回普通字典，非法输入
抛 `ValueError`。
